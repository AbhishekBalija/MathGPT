PRODUCT REQUIREMENTS DOCUMENT (PRD)
Project: MathGPT — Verified Step-by-Step Math Solver
Version: UI-Flow-Rev2

========================================================
1. PRODUCT OVERVIEW
========================================================
Goal:
A platform where students ask math questions through a chat-style interface and get a structured, verified step-by-step answer. UI is similar to ChatGPT: left = chats, center = conversation, right = answer tab.

Core Value:
- AI gives steps like a teacher (clear, justified, school-friendly)
- All steps are CAS-verified for correctness
- Clean productivity UI: chat left, answer right
- Easily review past solutions via sidebar history

A. Landing Page (Public)

========================================================
3. USER FLOWS
========================================================

Flow 1: Solve a Math Question
1. User logs in → sees 3-panel interface.
2. User types a math problem in chat window.
3. Send → User message appears in center panel.
4. Backend:
   - Sends prompt to LLM
   - LLM returns structured steps (JSON)
   - Verification engine checks each step
5. While backend works, right panel shows "working…"
6. When done:
   - Right panel shows the step-by-step verified solution.
   - Center chat shows a short summary message from AI.

Flow 2: View Past Solutions (History)
1. User clicks “History” in sidebar.
2. Sidebar shows a list of past problems.
3. Clicking a history item:
   - Loads chat thread in center panel
   - Loads verified solution in right panel

Flow 3: Profile Tab
- Shows:
  - Name
  - Email
  - Usage count
  - Premium status (future)

Flow 4: Settings Tab
- Theme toggle (light/dark)
- Clear history
- Math rendering preferences
- Notifications toggle

========================================================
5. BACKEND REQUIREMENTS
========================================================

Tech Stack:
- Backend API: Node/Express OR Motia orchestration
- Python microservice for SymPy verification
- Postgres (Supabase free tier)
- Optional: Redis for rate limits
- LLM: GPT or Claude

API Endpoints:
1. POST /api/chat/send
   - input: { chatId, message }
   - output: { messageId }

2. GET /api/solution/status?chatId=
   - polling or websocket for solution progress

3. POST /api/solution/generate
   - calls LLM
   - returns JSON steps
   - triggers verification

4. POST /api/solution/verify
   - Python/SymPy checks steps

5. GET /api/history
   - returns problem list

6. GET /api/history/:id
   - returns chat + solution data

Additional Backend Tasks:
- Save messages & solutions
- Generate PDFs via HTML-to-PDF service
- Step auto-correction loop with LLM

========================================================
6. VERIFICATION ENGINE DETAILS
========================================================

Verification Steps:
1. Convert each step expression into SymPy
2. Check:
   - Algebraic equivalence
   - Derivative correctness
   - Integral correctness (differentiate result)
3. If step invalid:
   - Generate error explanation
   - Ask LLM to regenerate only that step
4. Re-check
5. Mark steps:
   - VERIFIED
   - CORRECTED
   - FAILED (rare → fallback explanation)

Supported Problem Types:
- Algebra (equations, simplification)
- Differentiation
- Integration
- Limits (basic)
- Trig transforms
